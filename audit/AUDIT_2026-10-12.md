### Runtime (`runtime/rokr/src/lib.rs`)

- `rok_gc_alloc_slow` 의 `size.wrapping_add(align)` → wrap 시 작은 버퍼 할당 = heap overflow. `align` 2의 거듭제곱 검사 없음. (50-53)

### Frontend

- **scanner 가 주석/문자열 속 단어를 타입 이름으로 등록** (`rokc_scanner/src/lib.rs:49-80`). `// compute the struct size` → `size` 사용 불가. 비-ASCII 타입명은 반대로 미등록. → scanner 제거, 구문 기반 판단.

## P1 — 견고성 / spec 불일치

### 검사 패스 부재
- `rokc_check` (no-op) / `rokc_resolve` (33줄) 이 driver 에서 호출만 됨 → 검사 착시.
- 타입 불일치·인자 개수·return 누락·let-else 비발산 else 가 mlir-opt 에러로 늦게 거부. 없는 필드, 여분 필드는 통과.
- enum/sum match exhaustiveness 없음 (`lower.rs:4848`) → 런타임 SIGTRAP.
- 중복 struct 정의 시 StructId 어긋남 (244, 278, 285), 중복 진단 없음.
- 가시성 검사는 `5641` 한 곳뿐 — 비공개 메서드/필드/타입 외부 접근 통과.
- 연산자 디스패치가 trait 이 아닌 메서드 이름 (6114-6120). `impl Add` 없이 `fn add` 만 있어도 `+` 작동.
- 클로저 내부 `return` → `fn_ret_ty` 미설정으로 `-> ()` (3296).
- trait impl 의 누락/여분 메서드 미검증.

### 컴파일러 crash / hang
- lexer 잘못된 바이트 → 자기 재귀 (`lexer.rs:126-131`), `$` 20만 개 stack overflow. 재귀가 `skip_trivia` 도 건너뜀.
- parser 재귀 깊이 제한 없음 — `(` ~300개 abort.
- 단형화 깊이 제한 없음 (`lower.rs:6422`) — 무한 인스턴스화 hang.

### Lexer / parser spec 불일치
- 숫자: `0x`, `1__0`, `1_`, `0x_FF`, `1e` 통과, `.5` 미지원, `0b102` 두 토큰, `2i` 미지원, `1f32` 분리, 범위 검사 없음 (`300i8` 이 MLIR 까지) — `lexer.rs:415-512`.
- 이스케이프: `"\q"`, `"\x80"` 통과, `\u{110000}` 원문 잔류, 줄 잇기 미처리, 문자 리터럴 길이 미검사 — `lexer.rs:593-645`.
- f-string / raw string 식 위치 파싱 불가.
- `unsafe`, `using` 키워드 표 누락 (`token.rs:204-251`). `where` 절, 열린 범위 `..b`/`a..`/`..`, impl 내 `const`, `extern "C" { static mut }` 미지원.
- 제네릭: `skip_generic_params` 가 `>>` 모름 (1437-1458), impl/trait/alias 제네릭 버림 (479, 800, 1131), supertrait/where 토큰 skip (1113-1116).
- 컬럼이 바이트 단위 (spec 1.1.5 는 코드포인트), CR-only 줄바꿈, BOM, VT/FF, XID/NFC 미준수, 레이블 ASCII 한정.
- 오류 복구 시 `struct_expr_allowed`/`type_sum_allowed` 플래그 누수 (2430, 2600, 2657, 3059-3066) → RAII 가드로.
- 복구가 토큰 1개 skip → 연쇄 오류 폭주. item 키워드/`;`/`}` 동기화로.
- prefix 연산자 lookup 실패 시 진단 없이 문장 소실 (2161).

### Codegen / driver
- float `!=` 가 `one` → NaN 오답. `une` 로 (`emit.rs:1384`).
- `char` → i8 (spec 808: i32) (`emit.rs:1437`, 1169-1171).
- enum payload 첫 변형 타입만 사용 (`ty.rs:105-115`), sum 레이아웃 경로 2개 불일치 (`emit.rs:1278-1281`).
- 심볼 맹글링 (905) 없음 — `mod a { fn b }` vs `fn a__b` 충돌, 사용자 `malloc`/`rok_runtime_init` 충돌.
- `--target` 이 clang/mlir-translate 에 미전달.
- main 반환 i8/i16/bool 시 잘못된 `trunci` (192-200). static Float/UInt/Str 초기값 0 placeholder (1480-1492).
- shift ≥ 비트폭, 정수 overflow debug panic 없음.
- 미지원 연산을 `unrealized_conversion_cast` 가짜 IR 로 덮음; `codegen_with_target` 이 `Err` 를 안 냄.
- 임시 디렉토리 `$TMPDIR/rokc-build-<stem>` 고정 → 동시 빌드 충돌, 정리 없음, `create_dir_all` 실패 무시 (`main.rs:201-204`).
- CLI 가 901 과 크게 다름 (check/test/fmt/demangle/--emit/--release 없음, 패키지 대신 파일 입력, `emit` 이 cwd 에 덤프).
- `-L/--lib` 무시, `compile_source` 가 `source` 인자 버리고 재읽기 (`rokc_driver/src/lib.rs:75-76`).

### Runtime
- `rok_par_for`/`rok_par_scope` 가 callback 미호출 → 루프 본문 소실 (187-196). thread/task/coro 스텁 null 반환 (145-177). → 구현 전까지 `rok_panic("unimplemented")`.
- `rok_panic(code: i32)` vs spec 805 `(msg, len)`, 출력 stdout (spec: stderr). 진단 출력 전반 stdout.
- `rok_gc_alloc_slow` 헤더 미초기화, OOM 시 null 반환.
- `rok_par_for` callback 이 non-nullable fn 타입 → null 이면 UB. `Option<extern "C" fn>`.
- TLS 블록 (803) 없음 — 전역 `AtomicBool` 하나, export 도 안 됨.
- `ObjectHeader` `align(8)` / size 16 정적 검사 없음, `gc_flags` non-atomic.
- `rust_eh_personality` + compiler_builtins 심볼 export → 중복 심볼 위험.
- `rok_throw` 가 longjmp 대신 `exit(101)`.
- GC 없음 — 할당은 영원히 해제 안 됨.

구현률: 801 ~40%, 802 0%, 803 ~5%, 702 ~10%, GC/스케줄러/코루틴 0%, 805 심볼 ~95% / 동작 ~15%.
