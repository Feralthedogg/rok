## P0 — wrong code generation / memory safety

### HIR (`compiler/rokc_hir/src/lower.rs`)

Root cause: failure paths fall through to `ConstVal::Unit` / `HirTy::Unknown` without a diagnostic (31 places).

| # | Symptom | Location | Repro |
|---|---|---|---|
| H-C1 | Undefined names/functions compile as 0 | 6255 (`UnresolvedPath`), 5964, MIR `lower.rs:512` | `return yy + 1;` → exit 0 |
| H-C2 | Operator type mismatch → Unit | 6029-6033, 6096-6100 | `let a:i64=40i64; let b=a+2;` → b is Unit |
| H-C3 | Struct construction inside a module → Unit | 4251 (last-segment lookup vs the driver's `a::P` registration) | `a::P{x:7}.x` → 0 |
| H-C4 | Inferred instantiation of a generic struct → Unit | 4258-4292 | `Box{v:5}.v` → 0 |
| H-C5 | `for _ in`, `for v in f()`, `for i in r` → loop runs 0 times | 4515-4520, 4633-4645, fallback 3256 | `for _ in 0..4 {t=t+1;}` → 0 |
| H-C6 | Closure captures inside `for`/`??`/`?.`/`?` not detected | `_ => {}` in `closure_free_names_expr` at 3885 | expected 8 → 0 |
| H-C7 | `?` propagation misbehaves (non-sum return, sum without none, 3-variant sum) | 3757-3776 | returns 0 / runtime trap |

Fix: turn every fallback into `emit_error`. Make `UnresolvedPath` an ICE in MIR. Infer literals from the expected type (currently fixed to i32 at 6384).
Four AST walkers (1626, 1840, 2041, 3885) → one exhaustive `Visitor` in `rokc_ast`.

### Codegen (`compiler/rokc_codegen_mlir/src/emit.rs`)

| # | Symptom | Location |
|---|---|---|
| G-C1 | Constants emitted with the literal type instead of `dst_ty`, call types with the argument types → `g(3)` (i64 param) fails MLIR verification | 1124-1137, 1001-1006 |
| G-C2 | Per-function string intern table → using the same literal twice gives an undefined `@rok.str0` | 153-162, 278-285 |
| G-C3 | No division-by-zero / `MIN/-1` check (`7/0` → prints 0, exit 0) | 1351-1356 |
| G-C4 | No array bounds check (`a[100000]` → SIGSEGV) | 762-811, 493-540 |

### Runtime (`runtime/rokr/src/lib.rs`)

- `size.wrapping_add(align)` in `rok_gc_alloc_slow` → on wrap, a small buffer is allocated = heap overflow. No power-of-two check on `align`. (50-53)
- Safe `pub extern "C" fn`s dereference raw pointers in 12 places (71, 81-106, 231, 265, 305, 316). Includes the `printf("%s", NULL)` path.

### Frontend

- **The scanner registers words inside comments/strings as type names** (`rokc_scanner/src/lib.rs:49-80`). `// compute the struct size` → `size` becomes unusable. Conversely, non-ASCII type names are not registered. → Remove the scanner; decide syntactically.
- `a as i64 < b` swallows `< b` as generics, and a missing `>` is ignored (`parser.rs:2949-2956`, 1711-1725, 84-91). `fn f(x: Vec<i32)` passes.
- Compound assignment evaluates the left side twice: `a[f()] += 1` (`parser.rs:2090-2110`), violating spec 304.
- Tuple fields `t.1u8` / `t.0x1` → `t.0` (`unwrap_or(0)` at `parser.rs:2886, 2973`).

## P1 — robustness / spec mismatches

### Missing check passes
- `rokc_check` (no-op) / `rokc_resolve` (33 lines) are only called from the driver → illusion of checking.
- Type mismatches, argument counts, missing returns, and non-diverging let-else `else` are rejected late, as mlir-opt errors. Nonexistent fields and extra fields pass.
- No enum/sum match exhaustiveness (`lower.rs:4848`) → SIGTRAP at run time.
- Duplicate struct definitions misalign StructIds (244, 278, 285); no duplicate diagnostic.
- Visibility is checked in only one place, `5641` — access to private methods/fields/types from outside passes.
- Operator dispatch goes by method name, not trait (6114-6120). `+` works with just `fn add` and no `impl Add`.
- `return` inside a closure → `-> ()` because `fn_ret_ty` is not set (3296).
- Missing/extra methods in trait impls are not validated.

### Compiler crash / hang
- Invalid lexer byte → self-recursion (`lexer.rs:126-131`); 200k `$` overflow the stack. The recursion also skips `skip_trivia`.
- No parser recursion depth limit — ~300 `(` abort.
- No monomorphization depth limit (`lower.rs:6422`) — infinite instantiation hangs.

### Lexer / parser spec mismatches
- Numbers: `0x`, `1__0`, `1_`, `0x_FF`, `1e` pass; `.5` unsupported; `0b102` is two tokens; `2i` unsupported; `1f32` split; no range check (`300i8` reaches MLIR) — `lexer.rs:415-512`.
- Escapes: `"\q"`, `"\x80"` pass; `\u{110000}` left verbatim; line continuation not handled; character literal length unchecked — `lexer.rs:593-645`.
- f-strings / raw strings cannot be parsed in expression position.
- `unsafe`, `using` missing from the keyword table (`token.rs:204-251`). `where` clauses, open ranges `..b`/`a..`/`..`, `const` in impls, `extern "C" { static mut }` unsupported.
- Generics: `skip_generic_params` does not know `>>` (1437-1458), impl/trait/alias generics are dropped (479, 800, 1131), supertrait/where tokens skipped (1113-1116).
- Columns are in bytes (spec 1.1.5 says code points); CR-only newlines, BOM, VT/FF, XID/NFC not conformant; labels ASCII-only.
- `struct_expr_allowed`/`type_sum_allowed` flags leak on error recovery (2430, 2600, 2657, 3059-3066) → use RAII guards.
- Recovery skips one token → cascading error flood. Synchronize on item keywords/`;`/`}`.
- When a prefix operator lookup fails, the statement is lost without a diagnostic (2161).

### Codegen / driver
- Float `!=` uses `one` → wrong for NaN. Use `une` (`emit.rs:1384`).
- `char` → i8 (spec 808: i32) (`emit.rs:1437`, 1169-1171).
- Enum payload uses only the first variant's type (`ty.rs:105-115`); two inconsistent sum layout paths (`emit.rs:1278-1281`).
- No symbol mangling (905) — `mod a { fn b }` vs `fn a__b` collide; user `malloc`/`rok_runtime_init` collide.
- `--target` not passed to clang/mlir-translate.
- Wrong `trunci` when main returns i8/i16/bool (192-200). Static Float/UInt/Str initializers are 0 placeholders (1480-1492).
- No debug panic for shifts ≥ bit width or integer overflow.
- Unsupported operations are papered over with fake `unrealized_conversion_cast` IR; `codegen_with_target` never returns `Err`.
- Fixed temp directory `$TMPDIR/rokc-build-<stem>` → concurrent builds collide, no cleanup, `create_dir_all` failure ignored (`main.rs:201-204`).
- The CLI differs greatly from 901 (no check/test/fmt/demangle/--emit/--release, file input instead of packages, `emit` dumps into cwd).
- `-L/--lib` ignored; `compile_source` discards its `source` argument and rereads (`rokc_driver/src/lib.rs:75-76`).

### Runtime
- `rok_par_for`/`rok_par_scope` never call the callback → loop bodies vanish (187-196). thread/task/coro stubs return null (145-177). → `rok_panic("unimplemented")` until implemented.
- `rok_panic(code: i32)` vs spec 805 `(msg, len)`; output goes to stdout (spec: stderr). Diagnostic output goes to stdout throughout.
- `rok_gc_alloc_slow` leaves the header uninitialized and returns null on OOM.
- The `rok_par_for` callback is a non-nullable fn type → UB if null. Use `Option<extern "C" fn>`.
- No TLS block (803) — a single global `AtomicBool`, not even exported.
- No static check of `ObjectHeader` `align(8)` / size 16; `gc_flags` non-atomic.
- `rust_eh_personality` + compiler_builtins symbols exported → risk of duplicate symbols.
- `rok_throw` does `exit(101)` instead of longjmp.
- No GC — allocations are never freed.

Implementation coverage: 801 ~40%, 802 0%, 803 ~5%, 702 ~10%, GC/scheduler/coroutines 0%, 805 symbols ~95% / behavior ~15%.

### Tests
- Without LLVM tools both harnesses silently pass (false green).
- `librokr.a` is not rebuilt → tests run against a stale runtime.
- 172 of 190 integration cases check only the exit code. Negative tests only check "did it fail" → add an `// expect-error:` directive.
- 16 unit tests (14 in the parser). 0 for lexer/HIR/MIR/codegen/runtime.
- 0 probes covering spec 007/008/009 or the stdlib spec. 0 async/await/yield integration cases.
- 80 seconds = 190 cases serially × (build 0.1s + macOS first-run check 0.3s). Parallelize with `thread::scope`.
- `run_probes.sh` duplicates the logic of `spec_probes.rs`.

### stdlib
- Tier names: spec `rok::raw/hub/std` vs implementation·targets.md `unsafe/core/std`.
- lang slots: 29 in spec 004 vs 29 implemented, 8~9 overlap. 14 type slots, `panic_fn`, `try_branch`, etc. unregistered. No 6.4.7/6.4.8 checks.
- `LangTable` built and then discarded (`let mut _lang` at `rokc_driver/src/lib.rs:87`).
- `std/lib.rok`, `unsafe/lib.rok` are comments only. `core` has only trait declarations. ~5 of 20 hub modules.

## P2 — spec-internal decisions needed

- S1: 604 uses `add_trait` etc. as slot examples, but the "authoritative" 004 does not have them. The implementation follows 604.
- S2: precedence of `+` is 9 (301:91, 302:33, 604) vs 7 (302:57, 203-ops:17, implementation).
- S3: precedence of `??` / `..` — spec 302 table vs hard-coded in the parser.

- S8: 20 implementation-only runtime symbols (`rok_alloc/print_*/load_*/…`) missing from 805.

Whether top-level statements are allowed is also undecided (907 JIT cells allow top-level `let`/expressions → may conflict with principle 0.1.1 of AOT-equivalent semantics).

## P3 — repository / structure

- `impl/` is not a git repository, no CI → clippy enforcement / `cargo tree` isolation checks not applied.
- Stray dumps at the `impl/` root: `*.hir.rok` ×4, `*.mir.rok` ×3, `let_else.mlir`.
- `clap` → ~20 external crates, violating the zero-dependency policy (state an exception or parse by hand).
- `lower.rs` is 6770 lines; `lower_full` 646, `lower_call` 510, `lower_pattern` 320, `lower_expr` 314 lines. `LowerCtx` has 22 fields / `new` takes 17 arguments.
- `rokc_hir → rokc_parser` dependency (PrecTable/Fixity) → move to `rokc_ast`.
- `rokc_driver` depends on the unused `rokc_codegen_mlir`; the build pipeline lives inside the `rokc` binary → interface embedders (REPL/LSP) cannot build.
- Test location `compiler/rokc/tests/` vs targets.md `impl/tests/integration/`.
- `TokenKind::UserOp`, scanner `add_user_keyword` are dead code. Two fn-type parsers, four named-field parsers.
- All line numbers in `hardcoding.md` are stale; its "primitives auto-activated" description is inaccurate. `drift.md`'s "105 fully aligned" / "302 100%" are wrong.

## Recommended order

1. HIR `Unit` fallback → errors, codegen G-C1/G-C2.
2. Common AST Visitor, remove the scanner.
3. Division-by-zero, bounds and allocation overflow checks; mark runtime `unsafe`.
4. Real type checking + exhaustiveness in `rokc_check`.
5. Test harness (LLVM required, forced runtime build, diagnostic checks, parallelization).
6. git + CI, clean up strays.
7. Spec decisions (S1–S4, S9), then stdlib bodies.
