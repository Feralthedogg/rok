## 1. Compiler - HIR / types

- 🟢 Inference of an unannotated `let` from later uses (2.10.2, `lower/infer.rs`): when lowering the initializer, unresolved type parameters (generic calls, empty `[]`, generic struct literals, closure parameters without context, method path values) become inference variables (`#var N`). If a variable remains in the type, the rest of the block (the variable's whole scope - inner blocks / closures / async bodies included) is lowered as a probe, and `coerce` unifies slot and value (method arguments, argument slots, assignment, annotated `let`, struct fields, `return`). Other open `let`s inside the probe share variables (no nested probes - `let a = List::new(); let b = List::new(); a.push(b); b.push(1);`). Then everything is rolled back (`rollback_all`: functions / instances / caches / diagnostics created after the probe) and the initializer is lowered again with the solved type as the expected type. Function instances over variables get only a signature (`mono::var_instance`); struct / enum instances over variables stay in the table and are cleared at the end (`drop_var_instances`). Bindings from literals are weak, so a later concrete type of the same numeric kind wins (`ys.push(1); sum(ys)` → `List<i64>`). A remaining variable is a ``cannot infer the type of `x` (`List<_>`)`` error at the `let`; two disagreeing uses are a ``conflicting uses of `x` `` error (use site + secondary label at the deciding site), followed by the usual mismatch error. Per spec, only `coerce` sites decide variables - operators (`x + 1`) / f-strings / patterns / field reads do not - and different uses are not widened to a sum (`xs.push(none); xs.push(1)` conflicts); for sum types only one open member is unified. `addr_of` / `many_addr_of` on a `List` element explains that `xs[i]` is an `Index` call returning a copy (a `[..]` literal needs a `[T; N]` slot to be an array). Each open `let` lowers the rest of the block once more (compile time: free when there is no open `let`, within noise on the empty program / large cases). A method chain's receiver is re-lowered with the chain's expected type and used if that type comes out unchanged (`lower_receiver`).

- 🟠 Sum types are sets (2.6.4): every `HirTy::Sum` is built through `HirTy::sum`, which flattens nesting, removes duplicates and sorts into canonical order (`none` last, the rest by structural `Debug` rendering - the implementation-defined order of 2.6.4; struct / enum ids are program-global, so tags agree across modules). Canonicalization reruns after alias substitution. So `A | B` and `B | A` share layout / tags, and ordering between variants (`PartialOrd` / `Ord`, `min` / `max` / `clamp`) follows canonical order. A partial sum flows into any sum containing all of it (per-variant re-tag `resum` in `coerce`), a type-check pattern `v: A | B` accepts a partial sum of a larger sum, and passing `i32 | str | none` to `T | none` gives `T = i32 | str`.
  - Nested layers (generalizing Swift-style nested optionals): when a sum written in generic code (`T | X1 | ..`, including `T?`) receives a `T` whose members overlap the generic's own members (`none` or any other type), that layer is not flattened and `T` stays one member - `T | none` with `T = i32 | none` is `(i32 | none)?` (`HirTy::Sum([Sum([i32, none]), none])`), `T | E` with `T = i32 | E` is `(i32 | E) | E`. Without overlap it flattens as before. Written types always flatten (`(i32 | none) | none` = `i32 | none`, aliases too). The decision lives in `HirTy::sum` alone: a sum member that overlaps an outer non-sum member stays nested - written sums are flattened first by `ty::written_sum` / `HirTy::spread`, and only generic members (type parameters, `Self`, `T::X`, `<T as Tr>::X`) and `substitute_params` substitutions pass through as a single member. Each layer is canonicalized separately. Patterns / `is` / `?.` / `??` / `?` / narrowing act on the outer layer only; the remaining arm binds the inner `T`. Inner member values (`i32`, partial sums of the inner sum) are wrapped into the inner layer; members also present in the outer layer (the `none` literal, `E`) are outer. Nested values do not flow into flat sums (type error; diagnostics render `(i32 | none)?` / `(i32 | E) | E`). So `for x in xs` (`List<i32 | none>`), `get` / `pop` / `Dict::get` distinguish a stored `none` from "absent".

So zero-filled storage (a new `GcBuf` / `List` buffer / GC object) reads as `none` (case `gcbuf_zeroed_none`; the spec does not fix the layout). Enum tags are the variant number unchanged.
    - Associated types `Self::X` and generic alias parameters are generic members too: `Self::Item | none` in an impl method signature (`type Item = i32 | none`) and `Maybe<i32 | none>` of `type Maybe<T> = T | none` nest. A non-generic alias (`type Flat = Opt | none`) is a written type and flattens.     - `T?` type syntax (2.6.5): the parser produces `Nest(T) | none` - same as `Maybe<T>`, so `i32?` = `i32 | none`, `(i32 | str)?` flattens, and `(i32 | none)?` / `i32??` are two layers (the diagnostic rendering `(i32 | none)?` is valid source). Postfix `?` binds tighter than `|` (`i32 | str?` = `i32 | (str?)`, `fn() -> i32?` is a fn returning an optional, `(fn() -> i32)?` is an optional fn). The `?` in `x as T?` / `x is T?` belongs to the type (propagation is `(x as T)?`; the failed-cast diagnostic says so), and `??` there stays coalescing (`x as i32 ?? 0`). A written `T | none` stays a plain set sum. Diagnostics render a flat `T | none` as `i32 | none`. Library signatures still use `T | none`.

## 2. Compiler - front end

- 🟢 `#[literal(..)]` (6.5, `rokc_parser/src/literal.rs`): the pattern mini-language (`"tok"`, `expr` / `number` / `string` / `ident`, `{..}` / `(..)` groups, `% "sep"`, `*` / `+` / `?`, `, priority = N`) is written as tokens inside the attribute (the spec example form, not the `string_lit` of the 6.5.2 grammar). A driver pre-pass collects registrations from the library + user package; library ones are visible to every package, user ones only in that package. Three kinds:
  - Built-in shapes (`[..]`, `{k: v}`, `{a, b}`, `a..b` / `a..=b` / `a..` / `..b` / `..=b` / `..`): the parser parses them by the language rules (block vs set 6.5.6, range precedence) and HIR lowers them to a call of the handler registered for that pattern (core's `list_literal` / `dict_literal` / `set_literal` / `range_*_literal`). `[..]` in a `[T; N]` slot and tuples are built by the compiler directly (for fixed arrays the handler's `...T` is itself the array; a tuple handler would need heterogeneous `...`). `..=b` is `RangeToInclusive`.
  - `number "suffix"`: numeric suffixes that are not language suffixes (`2i`). The lexer keeps unknown suffixes and the parser turns them into a handler call (error if none). A user suffix in pattern position is a parse error.
  - Other patterns starting with a quoted token: tried by backtracking at every expression start, before built-in syntax; the longest match wins (`m[1, 2; 3, 4]`, `(x, y)@`). So a pattern starting with an identifier (`"m" "["`) shadows indexing of a same-named variable. Patterns starting with `expr` (left-recursive) are limited to the built-in range shapes.
  - Candidate selection (6.5.5): a handler whose return type's leaf name equals the slot type's, then the highest `priority`, else an ambiguity error. The slot type fixes the handler's type parameters (like a turbofish). HIR checks the handler signature against the capture count / repetition positions.
  - A `const fn` handler (6.5.8) runs at compile time when its arguments are constants and the result is embedded as a constant (`lower/const_eval.rs`, the const evaluation in §2 above). A panic / `throw` inside the handler is a compile error at the literal's location. With a runtime value among the arguments (`@(x, 1)`) it stays an ordinary call. If the result holds buffers / function values (`List`), it is only evaluated (error check) and the call is kept. A non-`const` handler is a runtime call.
  - Slices (`a[i:j]`) are language syntax, not literals (6.5.9). Two handlers with the same pattern, `priority` and return type (leaf name) are an error at registration; other duplicates are ambiguity errors at use. A nested repetition in a `...[T; C]` slot takes `C` from the first row (the 6.5.2 matrix example).
- 🟢 variadic `xs: ...T` (4.2.5): the parser types it `Slice<T>` (`desugar_variadic`); the call packs plain arguments into a fixed array viewed as a slice, or a fresh `List` when a `List` / `Slice` / array spread is mixed in (`lower_variadic`), so one instance serves every count. `...any` takes mixed types; a variadic passes on with `..xs`; `...[T; N]` with `N` unbound takes `N` from the first array literal. Tuple spreads fill the variadic position (`sum(0, ..t, 4)`). A `List` / `Slice` spread into fixed parameters fills the slots up to the next argument, length checked at run time (`index::spread_len`); an array spread fills its length. A Dict spread `f(..d)` (`d: Dict<str, V>`) fills still-empty parameters by key at run time (else default, else a missing-key panic); `V` must coerce to each parameter type; unknown keys panic (`index::spread_names`).
- 🟢 The parser runs on a 16 MiB thread: at the nesting cap it needs ~5 MiB (dev builds compile `rokc_parser` at opt-level 1; unoptimized frames were ~150 KB/level, 32-48 MiB) and ~4 MiB at opt-level 3 (`Expr` values are large), so a default 1-2 MiB thread does not suffice. The whole `rokc` command (HIR / MIR / codegen included) runs on a 1 GiB-stack thread, and the parser caps the total number of links in surrounding operator / postfix chains at 4096 (`expression chain too long`) - tree depth ≤ 256 + 4096. A 20000-term chain runs in 1 GiB; the HIR quadratic walks are fixed (`is_untyped_literal` / `const_int` check the right side first), what remains is mlir-opt/translate time growing with one function's size. A tool that calls the driver outside `rokc` (not the `rok` wrapper, which executes rokc) must use the same thread. These are implementation limits; the spec sets no nesting limit.
- 🟢 Value type limit (`collect::check_value_types`): a struct / enum (instances included) exceeding 65536 flattened scalar slots / an estimated 4 GiB is an error. Infinite size (a struct / enum / tuple / sum containing itself by value) is reported by the same pass at the declaration (for generic instances, at the use). The limit is spec 2.6's implementation limit.

- 🟡 GC-aware codegen (809 §8.9.9-12). Write barrier: before a `BufStore` / `HeapStore` (coroutine frames included) that writes a value holding GC references (a type with non-empty `gc_offsets`) into a GC object, an inline fast path is emitted (one monotonic load testing the `UNLOGGED | CARDED` bits (bits 6, 7) of `gc_flags`). If set: when `UNLOGGED`, call the slow `rok_gc_wb_slow(obj)`; then, when `CARDED` (old LOS object), mark the card inline (load the card table pointer from the word before the header, store 1 into the two bytes `(slot - obj) >> 9` and `(slot + value size - 1 - obj) >> 9` - an element may straddle a card boundary). Both bits are set together only on old LOS objects during concurrent mark (§5). So the barrier also takes the store address and value size. It is object-remembering, so q (the written value) is not inspected (q may be an inline `any` integer or a `str` interior pointer whose header cannot be read). Initializing stores into a freshly allocated object (`HeapBox`) have no barrier, since there is no GC point between allocation and store. `RawStore` (`Ptr<T>`, manual memory invisible to the GC), statics (roots) and stack arrays have no barrier. Atomics (`BufAtomic`) are integer / bool only, so none. Where the runtime writes references into GC objects (deque push / ring replacement / `out` of pop·steal) it uses `rokr_gc::write_barrier(obj, slot)`. Done: allocation of constant-size GC objects (`HeapBox` / `HeapAlloc`, under 8 KiB, align ≤ 8) emits the TLAB bump inline (load `rok_tls_tlab_cursor` / `_limit`, compare `limit - cursor` with the size, store `type_id` and `gc_word = size` in the header; on overflow `rok_gc_alloc_slow`). Runtime-sized `BufAlloc` still calls `rok_gc_alloc_slow`, which bumps the TLAB lock-free. Shadow stack and safepoint polls (see §8 GC roots): a relaxed atomic load of `rok_tls_yield_flag` after every function prelude and before every loop back-edge (found by DFS over the MIR CFG). A function with a loop keeps a shadow-stack frame even without calls. No "right after a call" poll (optional item of 804 §8.4.2). Root slots are zeroed right after their last use by MIR liveness (`rokc_mir::deaths`, backward dataflow): after a statement if a local it wrote / read dies after it; at block entry if a local live at the end of a predecessor dies on entry to this block (block params excluded). So function-level `let`s / temporaries are not roots after their last use (`gc_last_use_liveness`). `StorageDead` at the end of value blocks remains (liveness already covers it). `rok_tls_*` declarations use the initial-exec TLS model: MLIR's `llvm.mlir.global` has no TLS model attribute, so the driver rewrites `@rok_tls_*` declarations in the translated LLVM IR to `thread_local(initialexec)` (`toolchain::tls_initial_exec`; ELF uses `@gottpoff` / `:gottprel:`, Mach-O ignores it). ScanTable (802): `GcRef` → `STRONG_REF`, `str` ptr → `INTERIOR_REF`, `any` → `ANY_SLOT` (tag offset), enum / sum payloads that can hold references → `SUM_PAYLOAD` (§5 ScanTable; real `[GcRef; n]` arrays are now `STRONG_REF`s). `BufAlloc` buffers (storage of `List` / `Dict` / `GcBuf`) whose elements hold references are allocated with a type id registering the element type's table with `version` bit 15 (`TABLE_ARRAY`) (`total_size` = element stride, offsets relative to the element; instead of type id 2's "every word a candidate"). Derived pointers across safepoints: verified none - `BufStore` / `HeapStore` do address GEP → value load → barrier (not a safepoint) → store within one statement, and operands of calls / allocations (`Call`, `HeapBox`, `HeapAlloc`, `BufAlloc`) all come from MIR locals (shadow-stack roots, cleared only after the statement). Objects pointed to by roots are not moved (§5 GC), so SSA pointers derived from root values (even if LLVM keeps them across a call) stay valid. `size_align` does not reflect the `i64` alignment (4) of 32-bit targets. A loop with a constant trip count ≤ 64 whose blocks reach no safepoint has no back-edge poll (`rokc_mir::short_loops`, both backends); a function whose loops are all such loops can be quiet; a prebuilt function's inline copy counts for quietness.

- 🟠 `str` is a `(ptr, len)` value (808). Literals are static bytes; runtime strings are GC objects (type id 1, no children to trace; the GC treats `ptr` as an interior pointer). A slice is `(ptr + start, end - start)` sharing the original bytes (O(1); `lines` / `split*` / `trim*` / `strip_*` / `split_whitespace` copy nothing too), so `ptr` may point into the middle of an object or at its trailing NUL; the GC keeps the whole object alive through the interior pointer and fixes it on evacuation. Literals and whole runtime strings have a NUL after their bytes but slices do not, so when passing to C codegen wraps the call in `rok_str_cstr` (`ptr` as is if a NUL follows, else a pinned GC copy) and `rok_str_cstr_done` (unpin) afterwards; runtime libc calls use `os::cs` (malloc copy, freed on drop). A small slice keeping a large original alive is accepted. Remaining:
  - `str` is an immutable value; the mutable buffer is `StrBuf` (a handle over a GC `GcBuf<u8>`; `push` / `push_str` / `len` / `capacity` / `clear` / `to_str`; `push_byte` is the byte path and an `unsafe fn` - `to_str` hands the bytes out as `str` unchanged, so UTF-8 is the caller's responsibility (2.15.1); unknown bytes go through `str::from_utf8`; `push(char)` uses the runtime UTF-8 encoder `rok_buf_put_char`).
  - FFI: an `extern "C"` function is C ABI regardless of name: it takes `str` as `char*` (a `str` return uses `strlen`) and `fn` arguments as C function pointers. Runtime symbols are declared in `extern "rok"` blocks and take `str` as a `(ptr, len)` value and `fn` values as `{code, env}` (HIR fixes `FnFacts::abi` per function; MIR / codegen only read it).
  - `as_bytes` is a read-only `Slice<u8>` view over the string's own bytes (no copy: `rok_str_bytes_buf` gives a `GcBuf` word pointing `HEADER_SIZE` before the bytes; an interior object pointer for runtime strings, outside the heap for literals). `byte(i)` is an O(1) byte read. `s[a:b]` (`Sliceable<Range<usize>> for str`) clamps to the length, checks char boundaries, and returns a view. `StrBuf[a:b]` still copies the whole buffer and then slices. `trim` / case conversion are Unicode (`White_Space`, UCD 18.0.0 tables, §6); `split_whitespace` is Unicode too. Case conversion has no locale rules (Turkish i etc.).
- 🟡 extern "C" ABI (806): done - a C variadic declaration `fn printf(fmt: str, ...)` (§8.6.10; the parser records a `#c_variadic` marker attribute; outside an `extern` block it is a HIR error) becomes `llvm.func @f(.., ...)` + `llvm.call .. vararg(..)` (Apple arm64's "variadic arguments on the stack" is handled by LLVM via the call's fixed argument count). ## 4. Runtime (007 / 008)

- 🟠 The GC is mark-region (`runtime/rokr_gc`, the block / line structure of Immix 703 §7.3.1 + opportunistic evacuation, below; full collections of large heaps use concurrent mark, below). It reserves 64 GiB of address space as `PROT_NONE` and commits 32 KiB blocks one at a time (side metadata per block: state of 256 lines of 128 B, an object-start bit per 8 B granule). Objects under 8 KiB with align ≤ 8 are bump-allocated from a per-thread TLAB (a contiguous run of free lines, 702 §7.2.1); objects larger than a line that do not fit the TLAB get their own line range; 8 KiB or more / over-aligned / `type_id` 0 go to the LOS (one allocation each, linked through a prefix before the header, `LARGE` flag: from 64 KiB (`LOS_MAP_MIN`, prefix and card table included) pages of their own - `mmap` / `VirtualAlloc`, zero pages faulted in on first touch, unmapped by the sweep when the object dies; smaller ones (over-aligned small objects, objects just over 8 KiB) from the C heap, zeroed; wasm32 has no pages to return and uses a zeroed allocation. Case `gc_los_pages`: eight 64 MiB buffers with one byte written each keep peak RSS < 48 MiB, 194 MiB before). Every object's `gc_word` is its size (multiple of 8; during evacuation, the new address of a moved object), and block objects have non-zero `type_id`, so blocks are parseable (non-object memory is 0). Collection: stop all mutators, retire all TLABs (TLAB slots published in the registry), mark from all shadow stacks / the pin list / the remembered set; sweep marks lines of live objects and only clears the start bit of dead ones. Dead objects are not zeroed: the line ranges handed out by refill are memset in one go outside the world lock (the TLAB fast path still receives zeroed memory). Object lookup (interior pointers / candidate words) uses the per-block start bitmap (kept across collections); lines handed out since the last collection (`TAKEN`) are parsed only when a lookup first touches that block - a young block nobody points to is never read and is freed whole. A pin (`rok_gc_pin`) sets the flag and adds the object to a spin-locked list, so collection does not scan every header (`IMMORTAL` is never set and is ignored). When the heap (live after the last collection + TLABs / objects handed out since) exceeds `max(4 MiB, previous live × 2)`, collection happens at refill; `rok_gc_collect` collects explicitly; `rok_gc_stats_live_bytes` (exact live right after a collection, including all handed-out TLABs in between) / `rok_gc_stats_collections` are for tests. Remaining:
  - Mark: `drain` pops into a ring of 8 prefetched objects and scans the oldest; `push` does not read headers (drain tests the mark bit); a precise word resolves to the nearest start bit without reading the object's size (ambiguous words and the evacuation fix-up check it); buffers of plain references are scanned in one loop. A full-collection factor of ×3 / ×4 was measured and not taken (gc_retain_small worse; gc_fragment RSS up to +38%).
  - Generations (sticky mark-bit, 703 §7.3.2, always on): objects surviving a collection are old (`STICKY` + `UNLOGGED`; LOS objects `STICKY` + `CARDED`). A minor collection marks only from roots + remembered set + dirty cards and does not enter old objects (a block object is judged old without reading its header unless its line is `TAKEN`), and sweeps only lines handed out since the last collection (`TAKEN`) (unparsed blocks only change line state). Full collection when old bytes exceed `max(4 MiB, live after the previous full × 2)` and on `rok_gc_collect`. Remembered set: block objects (< 8 KiB) per object - the barrier slow path clears `UNLOGGED` and pushes the object lock-free into its thread's 4 KiB log chunk (803 `rok_tls_wb_log_cursor` / `_limit`). Full chunks, and all chunks at collection / thread exit, go to a lock-free stack drained by the collector. `UNLOGGED` again after a minor. Old LOS objects per card (512 B; the card table lives after the object in the same allocation, its pointer is the last word of the `Prefix` = right before the header): the barrier dirties the card, a minor scans and clears only dirty cards (full sweep clears the cards of surviving LOS objects). Diagnostics: `rok_gc_collect_young` (minor), `ROK_GC_STATS=1` (count / total pause / max / collector thread CPU time at exit), `ROK_GC_STRESS=N` (every allocation through the runtime gets a TLAB of exactly the object size, so all allocations take the slow path; collect every N, every 8th full). The integration suite passes under `ROK_GC_STRESS=50` (-O0) and `=20` (-O2) (excluding time-limited cases). Cases `gc_old_to_young` / `gc_old_to_young_cards` fail when built with a compiler without the barrier (log / card respectively). Measurement (`bench/`, -O2, macOS arm64, shared machine with load average 20~30, so minimum process CPU (user+sys) of 5 runs; GC as minimum collector CPU from `ROK_GC_STATS` over 3 runs - wall pauses swing 2~3× on this machine and are not used): table in the `bench/bench.sh` comments. Limits: the cost of parsing young objects is proportional to the number of blocks with survivors (nearly all if survivors are scattered). Nursery size is a fixed policy (collect at `live × 2`) with no tuning knob. Cards are for LOS objects only (objects under 8 KiB are rescanned whole).
  - Evacuation (opportunistic defragmentation of 703 §7.3.1, full collections only): precision - the heap is precise (ScanTable `STRONG_REF` / `INTERIOR_REF` / `ANY_SLOT` decided by tag / per-element buffer tables, §4 GC-aware codegen). Enum / sum payloads are precise too (`SUM_PAYLOAD`, ScanTable below). Only two kinds of ambiguous words exist: shadow-stack / static / spawn roots (may be inline `any` payloads, and pointers derived from root values - `str` bytes passed to C, element addresses - may sit in registers), and runtime word buffers (type id 2: deques and rings). Mark records the block objects reached through these (`pinned` list), and those objects are not moved in this evacuation (mostly-copying, Bartlett / conservative-Immix style). So GC pointers passed to blocking runtime calls / `extern "C"` stay put during the call: arguments remain in the roots until the call statement ends (MIR liveness clears them after the statement) and root targets do not move - a runtime function may hold pointers derived from its arguments across allocation / `enter_native` (the bucket address of `rok_sync_wait`: the waiting thread's root pins the object, so the waker computes the same address). Where an address is used as a number (`rok_task_key_i32` / `_usize` - `task::park` / `unpark` keys, `same_task`) the object gets `NOMOVE` (header bit 8, permanent; lifetime unaffected). Pinned objects (`rok_gc_pin`: `TASK_PARKING`, running executors) are not moved either. Behavior: right after sweep, if used blocks have ≥ 1/4 free lines and the free lines of blocks at most half full are ≥ 1/8 of used lines, those blocks are candidates (`select_candidates`, using the exact line state left by sweep - the Immix approach of choosing from the previous cycle's state before mark almost never chose anything, because young objects refill the holes and blocks look full). Live objects of candidates (except pinned / `NOMOVE` / ambiguously referenced) are copied into holes of other blocks → empty blocks → new blocks (up to candidate lines / 256 + 1), the old header gets `FORWARDED` + `gc_word` = new address, then one pass over the precise reference words of the whole live heap (block objects + LOS) fixes them (`fix_references`; interior pointers keep their offset). Candidate blocks' lines are recomputed. After a full collection, empty blocks beyond the next cycle's allocation budget (`next_gc - live`) return their pages to the OS (`mmap(MAP_FIXED)` maps fresh zero pages in place; reuse faults them in). `ROK_GC_EVAC=always` (always: every full collection moves every used block - for tests), second line of `ROK_GC_STATS` (block count, resident, evacuation count, bytes moved), `rok_gc_stats_moved_bytes`. Tests: `rokr_gc` unit tests (move / pin per reference kind, defragmentation), integration case `gc_evacuation` (every value kind intact after moving), `// gc-stress: N` directive (runs that case once more with `ROK_GC_STRESS=N ROK_GC_EVAC=always`, and again with `ROK_GC_STRESS=N ROK_GC_EVAC=always ROK_GC_CONCURRENT=always`; 22 GC / sync / async cases). The full integration suite passes under `ROK_GC_STRESS=50 ROK_GC_EVAC=always` (-O0) and `=20` (-O2) - excluding timing-dependent cases (the 50 ms wait in `async_cancel_io`, `async_send_backpressure`, the time limit of `async_spawn_throughput`). Limits: objects pointed to directly by roots, objects held in deques and objects used as park keys are not moved. Candidate selection is per line (no per-object hole statistics). Fixing rescans the whole live heap once more (recording only slots pointing into candidates during mark would require choosing candidates before mark). The LOS is not moved (as specified). Evacuation only in full collections. Raw pointers from `str::as_ptr` (stdlib 2.15.2): in a function whose types name a `rok::bare::ptr` type, every GC-ref local stays rooted (so in place) until its scope ends, and a coroutine keeps it in a pinning frame slot (`MirFunction::pins`, `UnionKind::Plain`). Open: a pointer stashed by a callee into a static from a function where no pointer type appears is not covered (the spec says so).
  - Concurrent mark (705, `rokr_gc::concurrent`): an automatic full collection marks concurrently when the old heap is 32 MiB (`CONCURRENT_MIN`) or more (SATB, Yuasa; one marker thread; minor stays STW). (1) Start pause: first a minor collection - so all live objects are old (`UNLOGGED`; LOS `CARDED`) and there are no `TAKEN` lines - then `UNLOGGED` is also set on old LOS objects (one LOS walk), roots / pins are pushed on the mark stack and the marker is woken. Roots are scanned per thread in this pause (the existing stop protocol = safepoint handshake). (2) During mark: refill hands out `BLACK` lines and LOS allocations are inserted before `los_mark_head`, so this mark neither reads nor sweeps them (line-granular allocate-black; young after mark). The barrier fast path is unchanged (one header load + and + branch, no global flag): during mark the first store into an old object finds `UNLOGGED` and goes to `rok_gc_wb_slow`, which, seeing the global `MARKING`, records every reference the object currently holds into the thread's SATB chunk (TLS slots `rok_tls_satb_cursor` / `_limit`, outside 803) and then clears `UNLOGGED` (per-object SATB - later stores only overwrite values stored during mark, so no recording is needed). Objects the marker already scanned (`SCANNED`) are not recorded. Among threads storing concurrently, the `SATB` bit lets only one record; the others wait until `UNLOGGED` clears (so nothing is overwritten before recording). The object also enters the remembered set (LOS: card) - it may point to young objects created during mark. The codegen barrier only changed order: slow path if `UNLOGGED`, then card if `CARDED` (old LOS objects during mark have both). (3) End pause: the marker when it runs out of work, or an allocating thread if the allocation budget (twice the young budget during mark) runs out first, stops the world, drains all threads' SATB chunks, re-pushes roots, finishes mark, and sweeps only the snapshot (`BLACK` → `TAKEN`). Live remembered-set objects from the mark carry over to the next minor (with `UNLOGGED` off), and LOS cards are not cleared. Sweep is STW (proportional to live objects: ~5 ms at 40~60 MiB live). No evacuation - if fragmentation shows after a concurrent mark, the next full is STW + evacuation (`stw_next`; fixing needs every slot stopped). Explicit `rok_gc_collect` is always STW (an in-progress mark is finished first). State ownership: block metadata is reserved once for all blocks (`mmap`) so its address never changes, and line state is read / written as atomic bytes; the mark stack / LOS index / block view moved into `Mark` (mark lock); the ScanTable table is replaced whole when it grows and the old one is never freed (read lock-free). `gc_flags` is atomic RMW from both mutators (`fetch_and(UNLOGGED)` / `fetch_or(SATB)`) and marker (`fetch_or(MARK | SCANNED)`). No io_uring; WASI preview 1 cannot create sockets, so on wasm32 nothing is watched and the driver never starts (being replaced: see the WebAssembly entry). `rok_io_register(fd, interest, waker)` / `rok_timer_register(deadline, waker)` (805 §8.5.5) and `rok_coro_park(frame, waker)` / `rok_coro_unpark(frame)` (708 §7.8.8) are runtime symbols that call the four rok `extern "C" fn`s installed with `rok_task_hooks_install(io, timer, park, unpark)` when the executor starts (defining them in rok with `#[export_name]` would compile the executor into every program: hello world +0.25s / +110KB). The waker is a one-slot `GcBuf<Waker>`, `interest` 1 = read, 2 = write (always edge-triggered, one wakeup; wakes immediately if the fd is already ready or cannot be watched), `deadline` is ns of `rok_time_now_ns`, `frame` is any GC object (its address is the parking key - `rok_task_key` sets `NOMOVE` on it so evacuation does not move it). Calling outside the executor is fatal. Used by `async_runtime_abi`. Timers are the executor's `BinaryHeap` + `rok_time_now_ns` (allowed by 7.7.5; not the recommended timing wheel). Closing or shutting down a socket (`Sock::close` / `shutdown`) unparks both readiness keys of its fd (`task::wake_io`, a low-level stdlib 2.18.1 function), since no poller reports it (kqueue drops a closed fd's filters, Windows cancels the AFD poll): the waiter retries and sees EOF after `shutdown`, `InvalidInput` after `close` (case `async_net_close_wakes`). Linux keeps a stale epoll registration of a closed fd whose description a `try_clone` dup still holds (spurious wakes only; no `EPOLL_CTL_DEL` on close).
- 🟠 Executor (`library/core/src/task.rok`): one per process, started on first use (`static EXEC`): as many resident worker threads as CPUs + a blocking lane (`spawn_blocking`) + the I/O driver. Options read at start (`rok_sched_workers` / `rok_sched_mode`): `ROK_WORKERS=<n>` pool size; `ROK_THREAD_PER_CORE=1` (7.6.8) - every task gets a home worker (the spawning pool worker, else round robin `signal[HOMES]`), queued only on its local queue (`TaskRef.state[5]` marks real `spawn_local`s, so handoff still works); `ROK_DYNAMIC_WORKERS=1` (7.7.8) - `signal[ACTIVE]` wake targets: the last active worker going idle parks, a push finding all active busy activates one more. Cases `706_8_thread_per_core`, `707_8_dynamic_workers` (`// run-env:`). `block_on` and sync `par::*` attach the calling thread as a guest worker and run until the future completes and so do the `spawn_local` tasks pinned to that guest (no pool per call; `spawn` tasks keep running after `block_on` returns; local tasks may hold non-`Send` values, so no other thread takes them over - case `218_block_on_local_tasks_finish`). Wake latency of a guest's local tasks was measured equal to a pool worker's (http stone https_h2 with its TLS reader / writer pinned to the guest: 6-10 s vs 8-13 s pinned to a pool worker, on a loaded machine). Each worker has a local queue (`spawn_local`, never stolen) + a deque; wakes from guests and non-workers go to the injector. Queues are `Mutex<Deque<TaskRef>>`. Idle workers process timers and sleep on their own word with `rok_sync_wait` (until the next timer); `help_until` sleeps on an epoch word woken by pushes / finished tasks (no polling). A running worker is pinned in TLS slot `rok_tls_task_worker`. Async waits: `Mutex::lock_async`, `Receiver::recv_async` / `for await v in rx` use the process-wide parking table (`static PARKING`, `task::park` / `unpark`, key = a fixed GC address from `rt::key`); same-task / same-buffer checks use `buf_same` (`rok.buf.same`, pins nothing). Remaining:
  - The worker deque is the runtime's lock-free Chase-Lev deque (`rok_deque_new` / `_push` / `_pop` / `_steal`, `rokr/src/deque.rs`). An item is one GC reference word (a `GcBuf<TaskRef>` holding the `TaskRef`, one allocation per schedule), and the deque and its ring are word-traced GC objects, so tasks living only in a deque are traced through the deque handle. After ring growth the old ring is reclaimed safely at the next collection, since deque operations contain no safepoint. The owner also steals (FIFO) from its own deque: with LIFO, a task waking itself with `yield_now` would starve the rest of the deque (no LIFO slot). Tasks woken by a worker of another pool go to the injector (only the owner pushes to a deque). The local queue and injector are multi-producer and still rings behind a spin lock (`sched_yield`). Stale slots below top keep their references until overwritten (one ring's worth). An idle worker raises its sleep flag and sleeps on its own word at once (no spinning or yielding: a yielding searcher whose pushes woke nobody made every wake wait a time slice on a loaded machine). A push wakes one sleeping worker (`spawn_local`: the home worker) and leaves it searching (`WOKEN`, counted in `signal[SEARCHING]`); pushes while a woken worker searches wake nobody more, and the last searcher to find a task wakes the next one (tokio's scheme). Timers are a `Mutex` heap per pool (allowed by 7.7.5; the recommended timing wheel when O(1) insert is needed). The parking table is one global lock + `Dict<key, List<Waker>>`.
  - Timers are processed by idle workers, and busy workers also process them once every 32 tasks (otherwise, while a never-parking task - a `yield_now` loop - exists, every `sleep` waited forever).
  - Throughput: in the debug runtime, spawning + joining one tiny task takes ~30-50µs, mostly allocation / GC (a dozen GC objects per task: state / poll buffers, closure env, `Mutex<List<Waker>>` joiners ..). `async_spawn_throughput` runs 100k tasks in batches of 1000.
  - `task::spawn` takes a `Future + Send` `where F::Output: Send` (projection bounds were already supported in where clauses; `async_spawn_output_not_send` / `_send`). `AsyncFuture<T>` is `Send` if `T: Send`, and separately a HIR post-pass (`lower::send_check`) examines coroutine frames: (1) per coroutine, whether captures, locals used across an `await` (approximated in HIR evaluation order: declared before a suspend and used after; loops are walked twice) and temporaries live across an `await` (the earlier operand in `f(cell, await x)`) are all `Send`; (2) a whole-program (post-monomorphization) flow analysis of which values may hold such a non-`Send`-frame coroutine - following locals, parameters, return values, struct / tuple / sum fields, buffers a callee stores into via a parameter (`List::push`), closure captures / calls, and other coroutines' frames (futures held across `await`); (3) rejecting `task::spawn` and the thread-crossing `thread::spawn` / `Builder::spawn` / `par` `Scope::spawn` / `task::spawn_blocking` when an argument may hold such a coroutine. Values of types that cannot contain `fn` values, or with an explicit `unsafe impl Send` (`Task<T>` etc., excluding coroutine wrappers), are treated as holding nothing. Limits: context-insensitive, so calls to one function instance share parameters / results (pushing into two `List<AsyncFuture<i32>>` of the same element type looks like one list → conservative rejection), and stores through aliases the callee did not receive as parameters are missed. The precise solution is putting the `Send` bound directly on each coroutine's anonymous future type (4.1.11).
  - Cancellation (2.18.4, 707 §7.7.10): `Task::cancel` sets a flag and wakes the task. Every `await` checks `task::cancel_requested(ctx)` on entry, after receiving `Ready`, and right before suspending, and if true leaves the body like `return` (running `finally` / `using` drops on the way; the result is a zero value that the executor discards). Nested coroutines unwind innermost first (after resuming, the awaited future is polled first). Synchronous syscalls (blocking `read` etc.) are not cancellation points. Async waits (`*_async` socket I/O, `readable` / `writable`, `sleep` / `timeout`, `lock_async`, `recv_async` / `send_async`) resume immediately on the `cancel` wakeup and leave at the next `await`. A finished task removes its wakers left in the parking table (`TaskRef.parked`: list of parked keys, under the parking lock; already-unparked keys are pruned every 16), and timer entries of cancelled tasks are removed lazily: timers of finished tasks wake nobody and are left alone, and when the number of cancelled tasks holding timers since the last sweep reaches half the heap, one O(heap) sweep removes all entries of finished tasks (amortized O(1) per cancel; `bench/timers.rok`: 20k cancels 30-50s → ~130ms, insert / fire unchanged at ~100ms). Entries left by live tasks (`timeout` finishing first, the losing `sleep` of a `select`) stay until their deadline, causing one spurious wakeup. Checked via `task::registrations()` (parked wakers + pending timers of unfinished tasks, diagnostic) (`async_cancel_io`). A task cancelled during a poll is polled once more (the `await` of that poll already saw the flag) to take the cleanup path - only a task cancelled before its poll starts is finished even when Pending (hand-written futures without cancellation points). `await` on a cancelled task panics; `try await t.join()` throws `CancellationError`. `lock_async` / `read_async` / `write_async` (RwLock) do not lock on a cancelled poll and return Pending (had they locked, the `await` would leave after Ready, drop the guard, and leak the lock). `recv_async` / `for await` likewise take no value on a cancelled poll (it stays in the channel; the suspended-receiver mark is cleared), and `send_async` does not send (`async_cancel_waits`). A cancel arriving right after a poll took a value does not lose it: the "after Ready" check of `await` looks at `task::unwinding(ctx)`, not the bare flag (`cancel_requested`) - a mark set only once a cancellation point actually starts leaving (`state[4]`; set on the cancel's origin task / proxy when `cancel_requested` returns true). So values handed over by hand-written futures (messages, guards) are used and the next cancellation point leaves; a zero-value Ready from an inner coroutine that left due to cancellation still makes the outer one leave. A task cancelled after its last cancellation point produces its result and finishes normally (`join` / `await` return it; `CancellationError` only for tasks with `unwinding` set - finished without a result). `Blocking` (`spawn_blocking` / `fs::*_async`) returns Pending on a cancelled poll, so a waiter cancelled meanwhile drops the result even if the job finished first (`218_cancel_blocking_result_dropped`).
  - `TaskId` (like tokio's `task::Id`). Adding `task::id` exposed a name resolution bug, now fixed: a non-generic `task::id` brought in by glob (`use rok::core::**`) was found before the current module's generic `fn id<T>` (`lower_call` looked at the non-generic table first); now non-generic / generic fns resolve together in one value namespace (`resolve_any_fn`: the nearest of current module → `use` → `rok::core::**`, regardless of kind) (`generic_id`, probe `210_5_generic_default`, case `use_glob_private_core`). Globs (`use a::*` / `**`, implicit `rok::core::**`) import only items visible from the resolving module (`NameSet::visible`; types / variants too) - core's private helpers no longer clash with user names (bigint's `int_` / `nat_` prefixes remain from the earlier workaround). API: `task::id()` (panics outside a task), `task::try_id() -> TaskId | none`, `Task::id()`. A process-wide counter (`static Atomic<u64>`, from 1, never reused), `PartialEq` / `Eq` / `Hash` / `Display` / `Debug`, `as_u64()`. The current task lives in a per-worker slot of the pool (`running`), swapped by `run` around each poll (nested runs inside `help_until` restore it). `none` on `spawn_blocking` threads.
  - Future `select`: `task::select(futs: List<F>) -> SelectFuture<F>`, `Output = (usize, F::Output)` (index and value of the first future to finish). Why list-based: every `async { }` block is `AsyncFuture<T>`, so futures with the same output type fit one `List`, and different outputs are wrapped as `async { Msg::A(await a) }` (core has no 2-arity `Either`). Polled in list order inside the waiting task without spawning (earlier index wins when ready together). Children are polled with the Context of a per-select proxy task (`state[3]` mark, `up[0]` = parent waker; never queued): the proxy's wakeups go to the parent (until the proxy finishes), and `cancel_requested` follows the proxy chain to the parent's cancel flag too (parent cancellation reaches the children's `finally`). When one finishes, the proxy becomes `DONE` + cancelled, the remaining started (polled at least once) ones are polled once more with that Context to run `finally` / `using` and are dropped, then parking entries and timers registered under the proxy are removed (like a finished task) - a select in a loop accumulates no registrations (`async_select`). Never-polled ones do not run. Ordinary tasks' `up` share one empty buffer of the pool (no per-task allocation). Caution: zero-filled slots of `GcBuf<Struct | none>` are not `none` (read as the struct) - new buffers write `none` explicitly (`running`, the select proxy slots). An empty list panics. Unlike `Race` (a list of spawned `Task`s), the losers are stopped.
  - channel: `Sender::send_async` (`try await tx.send_async(v)`, suspends the task on a full bounded / rendezvous channel; sender parking key = `meta` address + 1). Rendezvous `try_send` also counts receivers suspended in `recv_async` / `for await`.
  - `RwLock::read_async` / `write_async` (`ReadFuture` / `WriteFuture`), `Condvar::wait_async(guard)` (`CondvarWait`, `g = await cv.wait_async(g)`; same shape as `Mutex::lock_async`). Both keep a "task parked" mark word (`[1]`) next to the state word: park → mark → retry, and the releasing side (`RwLock` guard drop, `notify_*`) calls `task::unpark` (global parking lock) only when marked. `notify_one` wakes the oldest blocked thread (`rok_sync_wake_one`) but every `wait_async` task (a stale parked entry could swallow the notify). `wait_async` releases the mutex on first poll and relocks with `lock_async` after notify. Cancellation while waiting does not block the worker: if the mutex is free it takes it and leaves (the `using` guard releases it); if another task holds it, that task's next `unlock` is recorded as a "debt" (`Mutex::owe`: (mutex key, task id) in the global `OWED` list, count in mutex `state[1]`). `unlock` consults the list only when `state[1] != 0`, and if the current task owes an entry, removes it and does nothing - the leaving task's guard drop does not release someone else's lock (`async_cancel_waits`). One global list (a debt lives only until the cancelled wait's guard is dropped); debts of tasks that ended without dropping the guard remain (harmless, that task id never returns; but `state[1]` makes every unlock of that mutex consult the list). No writer preference (writers can starve under a steady stream of readers, same as the sync version).

## 5. Standard library (refs-standard-libraries)

- 🟠 Numbers (2.1) remaining:
  - `int` / `float` (2.1.2-2.1.3, 2.1.7) are `Int` in `library/core/src/num/bigint.rok` / `Float` in `bigfloat.rok`. The structs carry `#[lang("int_type")]` + `#[keyword("int")]`: `#[keyword]` on a struct is a type keyword, so the `int` token becomes the struct path (`rok::core::num::bigint::Int`) in every package, and `int::` works as in `int::from_i64` (`let int` in name position is an error). Within `f64`'s normal range it is an `f64` itself (`e == 0`), so arithmetic matches IEEE 754 (`0.1 + 0.2 != 0.3`, NaN / ±inf / -0); only finite results leaving the range (overflow, underflow, subnormal) are promoted to `m * 2^e` (`1 <= |m| < 2`) - still correctly rounded to 53 bits (nearest-even). - 🟠 Conversion (2.11) remaining:
  - `Into` / `TryInto` / `SaturatingInto` / `WrappingInto` are traits with one generic method (`fn into<T: From<Self>>(self) -> T`) and a blanket impl over every type. So a bound like `T: Into<i64>` cannot be written (use `U: From<T>`). The conversions themselves are `From` / `TryFrom` / `SaturatingFrom` / `WrappingFrom` impls.
  - `TryFrom<U>` throws the associated type `type Error = ConversionError;` (default, `rok::core::error::ConversionError { msg }`) (`throws (Self::Error)`). Numeric impls (integer pairs, `int` / `float`, `char` from `u32` - spec 2.15.4) use `type Error = OverflowError;`, `Path` uses `NonUtf8Error`. `try_into<T: TryFrom<Self>>` is `throws (T::Error)`. It flags a use, on any path, of a place overlapping one that `Mutex::new` / `RwLock::new` / `send` / `try_send` / `send_async` / `Handoff::new` took, and of a guard's value (`get` / `set` / `update`'s captures) after the guard's `drop`. A value copied out of a gone one is gone. Calls go through per-function summaries (hands over, returns or a part of it, stores into another parameter's object or a `ref` parameter, captures into the returned closure, ties to a guard parameter), a fixpoint over the call graph. Generic functions and trait methods are their instances / `any` dispatchers; a call through a function value joins every function used as a value with those parameter types (closed world, `#fn` entries for dependencies); `extern` functions and intrinsics keep nothing; `Handoff::new` is not exported. Prebuilt libraries keep summaries in ROKHIR (v5; v6 adds exit kinds); the incremental front end needs nothing (the pass reruns over replayed bodies). Re-arming: assigning a variable or field (after `t = s`, assigning `t.f` splits the copy), `set` after `get`, `clone()`. Exempt: `Sync` uses, `unsafe` (4.15.2), a `match` / `is` on a variable, compiler temporaries, a `ref` parameter's copy-out. Messages name the owner, the user's lock variable, the alias, the call route (`` `xs` was moved into a `Mutex` by `store(xs)` at line 7 (inside `store`, line 12) ``), a loop pass, a value returned out of `using`. Cases `handoff_ok` / `handoff_{lock,guard,send,alias,call}_errors`, cli `prebuilt_dependency_keeps_handoff_summaries`. Library: the `Handoff` reads go through `cell.get()`; TLS `SessionCache` / `TicketStore` keep their own copies. Conditions are followed through tags: paths stay apart by what they know of a `bool`, a sum or enum variant, or a carrier's error or value (set by a constant, a copy or a call), and `if` / `while` / `match` (also `catch`, `try?`, `??`, `is`) pass only the paths their test may let through; paths with the same places gone are one, and past 8 paths or 8 loop passes all are one. Summaries record what each exit kind hands over, by the tag of the returned value (`x` lines, ROKHIR v6), so a caller's `catch` / `else` / `??` path sees only that kind's hand-offs; a `TryAsyncFuture` carries the tag its body ends with, and `poll` yields an error only from an erroring body, so `try await f(xs) catch` sees only `f`'s error-exit hand-offs. Remaining: a flag computed or compared (`n == 3`, `a && b` of unknown values) is not followed; neither is the value inside an `async fn`'s result (`none` from an `async fn -> T | none`: only error or not), nor a call's outcome stored into a field or a list; an item read out of a buffer is a value of its own (reading it back after handing it, or the buffer, over is not caught). The http stone still needs its redirect inputs kept aside and its h2 retry copy (real hand-offs on those paths) and `h2_ready` (an `async` `none` result); its `h1_head` split and the h2 `fields = []` re-arm are no longer needed.

With a `Slice<u8>` expected (alone, or in a sum without an array) it is a view. `include_str!` / `include_bytes!` are folded by the parser (`include_macro`), relative to the calling file. Library: `List::truncate` / `drain`, `Slice<u8>::find` / `List<u8>::find<B: AsBytes>` (naive O(n·m); `AsBytes` lives in core, re-exported by `std::io`), `str::from_utf8_lossy`, `AsBytes for [u8; N]`. Aggregates over 64 bytes (8.6.6) move through memory in both backends (memcpy / memset, built in place; `t = rv; x = t` builds `x` (`rokc_mir::copy_into`); the returned local is built in the caller's result, which a caller passes as a fresh slot for an address-taken local); a big array of constants is one copy from constant data. Remaining: aggregate block parameters are SSA values; a call result stored into a field or GC object goes through a temporary.
